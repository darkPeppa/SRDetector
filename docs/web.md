# Веб-интерфейс

```bash
docker compose up web            # http://localhost:8080
SRDET_WEB_PORT=9000 docker compose up web
srdet web --port 8080            # без Docker (нужен srdet-sim в PATH или SRDET_BIN)
```

Сервер — FastAPI внутри того же образа, что и CLI. Каждый запуск из браузера выполняет обычную
команду `srdet ...` в фоне, поэтому результаты, бэкапы и архивы получаются такими же, как из
терминала, и видны в обоих местах. Задачи выполняются по одной: каждая симуляция и так занимает
все ядра. Журнал задач хранится в `runs/web_jobs/` и переживает перезапуск сервера. Библиотеки
интерфейса (Alpine.js, Plotly, marked, JSROOT) подгружаются с CDN, так что браузеру нужен интернет.

## Разделы

| Раздел | Что можно делать |
|---|---|
| **Дашборд** | число прогонов, исследований и оптимизаций; лучшие найденные конфигурации; задачи; последние прогоны; кнопка быстрой проверки физики |
| **Моделирование** | выбрать базовую конфигурацию и изменить любой параметр `defaults.yaml`: материалы, покрытия и сенсоры выбираются из каталогов с подсказками, величины задаются с единицами, спектр пучка — отдельным редактором. Неактуальные поля скрыты (например, `sigma` только для гауссова пучка), изменённые подсвечены. Справа живой предпросмотр геометрии: сота с размерами, доля сцинтиллятора, число сот, разрез по оси пучка, проверка допустимости. Кнопки: показать макрос Geant4, запустить, запустить вместе с 3D-картинками |
| **Прогоны** | таблица с ключевыми метриками и фильтром; галочки для сравнения. Страница прогона: метрики с русскими подписями, все графики анализа (по клику увеличиваются), геометрия (интерактивная решётка всех сот с масштабом колесом и сдвигом мышью, крупный план соты, разрез, 3D-картинки Geant4), ROOT-браузер JSROOT по `srdet.root`, конфиг и макрос, файлы, лог; «повторить с изменениями» переносит конфиг в форму |
| **Исследования** | карточка каждого U/B/F-исследования: вопрос, на который оно отвечает, сканируемые значения, число прогонов, закреплённые условия и раскрывающееся «почему так» (почему выбраны эти условия и значения, чего ожидать, как читать график); запуск quick или полный с архивом и своим числом событий; отчёт с пояснением, картинками и интерактивным графиком по `results.csv` (оси и серии выбираются) |
| **Оптимизация** | конструктор спецификации: пресет, базовая конфигурация и закреплённые ключи, свободные параметры (диапазоны с единицами, log, варианты галочками), вычисляемые ключи, цель с расшифровкой словами, ограничения, Парето, метод и статистика по ступеням; живая проверка и план поиска (сколько симуляций и событий на каждой ступени), quick / полный запуск, сохранение пресета, YAML ([подробнее](optimization.md)). Дашборд результата: вкладка «метод и цель» (что и как искали, факт по ступеням), прогресс идущего поиска, цель ± σ, лучшие параметры, сходимость, фронт Парето, параллельные координаты всех допустимых испытаний, чувствительность к каждому параметру, проверенные кандидаты, таблица испытаний со ссылками на прогоны, геометрия лучшей конфигурации; кнопки «прогнать лучшую», «3D лучшей», скачать `best.yaml` |
| **Сравнение** | выбранные прогоны рядом: таблица метрик и столбчатая диаграмма |
| **Задачи** | очередь, статусы, живой лог, остановка |
| **Документация** | все документы `docs/`, README, отчёты исследований; ссылки на картинки и между документами работают; список архивов `results/` для скачивания |

## Новое в интерфейсе

* **3D-моделирование.** На странице прогона вкладка «3D» показывает геометрию и треки Geant4: γ, e⁻,
  e⁺ и каждый N-й оптический фотон. Можно выбрать событие (камера наводится на него), включать и
  выключать типы частиц, менять прозрачность сот, запускать анимацию пролёта и сохранять PNG. Треки
  пишет C++ (`/srdet/out/tracks N` → `tracks.jsonl`; в YAML `run.tracks`). Если у прогона их нет,
  кнопка «Смоделировать для 3D» делает короткий прогон с той же конфигурацией и привязывает его к
  исходному.
* **ROOT-браузер** на JSROOT: список объектов файла; гистограммы рисуются по клику; для деревьев есть
  выражение и условие, как в `TTree::Draw`. JSROOT настроен на один диапазон на запрос
  (`settings.MaxRanges = 1`), потому что многодиапазонные ответы сервера он не разбирает.
* **Оптимизация → «параметр → гистограммы».** Для выбранного параметра поверх друг друга
  рисуются гистограммы симуляций, где отличается только этот параметр, а справа — итоговая метрика.
  Кнопка «Досчитать скан» (`srdet optimize --resume DIR --scan L --points 6`) добавляет N значений
  параметра по всему диапазону вокруг лучшей точки.
* **Экспорт.** Кнопки «⬇ Excel» и «⬇ ZIP-пакет» есть на страницах прогона, исследования и оптимизации
  (`srdet export DIR [--format zip]`). Excel содержит сводку с русскими подписями, параметры, таблицы с
  описанием столбцов, гистограммы и графики. ZIP добавляет CSV, Parquet, PNG, конфиги, ROOT-файл и
  README. На вкладке «файлы» любой файл скачивается отдельно.
* **Тур** «❓ Как пользоваться» подсвечивает элементы текущей страницы и объясняет их по шагам. Полная
  инструкция со скриншотами: [user_guide.md](user_guide.md). Скриншоты обновляются командой
  `python tools/ui_screenshots.py --annotate --out docs/img`.

## Темы оформления (скины)

```bash
docker compose up web-pink    # http://localhost:8081   (srdet web --skin pink)
docker compose up web-rap     # http://localhost:8082   (srdet web --skin rap)
```

Функциональность та же, меняются цвета, шрифты, подписи и декоративный слой.

* **pink** — глянцевый розовый, блёстки, бабочки, сердечки с именами «Егор Крид» и «Екатерина
  Шульман», эстетика в духе кукол Bratz (без логотипов и официальных изображений бренда).
* **rap** — тёмная «сцена», неон, граффити-теги и стикеры: Замай, Слава КПСС, Oxxxymiron, Ежемесячные,
  «альтушечно»; батловая лексика в подписях.

Подписи и слоганы написаны своими словами. Тексты песен не используются, они защищены авторским
правом. Чтобы в сердечках и стикерах появились картинки, положите свои PNG/JPG в
`python/srdet/web/static/themes/<pink|rap>/user/`. Папка исключена из git, так что изображения
остаются только у вас. Словари тем лежат в `themes/pink.js` и `themes/rap.js`, движок — в `themes/skin.js`.

## Безопасность

Интерфейс рассчитан на локальную работу: порт проброшен на `localhost`. Наружу его открывать не
стоит, потому что авторизации нет. Файлы отдаются только из `runs/`, `results/`, `docs/`,
`configs/`, `legacy/`, с защитой от выхода за пределы этих папок. Задачи — только фиксированные
подкоманды `srdet` с проверенными аргументами.

## API (для скриптов)

| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/schema`, `/api/catalog`, `/api/configs[/{name}]` | поля формы, каталоги, конфигурации |
| POST | `/api/macro` | макрос для `{base, overrides}` |
| POST | `/api/jobs` | `{kind: run\|vis\|tracks\|scan\|study\|optimize\|validate\|archive, ...}`; для `optimize` можно передать `spec` из конструктора |
| GET | `/api/jobs[/{id}]`, POST `/api/jobs/{id}/cancel` | задачи |
| GET | `/api/runs`, `/api/run?path=`, `/api/run/geometry?path=` | прогоны |
| GET | `/api/studies`, `/api/study?path=` | исследования |
| GET | `/api/optimizations`, `/api/optimization?path=` | оптимизации (с прогрессом и планом) |
| GET | `/api/optimize/meta` | метрики с описанием, настраиваемые ключи, базовые конфигурации |
| POST | `/api/optimize/check`, `/api/optimize/save` | проверка спецификации и план поиска; сохранение пресета |
| GET | `/api/docs`, `/api/doc?path=`, `/api/archives`, `/files/{path}` | документы и файлы |
| GET | `/api/run/hist?path=&name=` | гистограмма из srdet.root (массивы) |
| GET | `/api/export?path=&fmt=xlsx\|zip` | читаемый экспорт (скачивание) |
| GET | `/api/skin` | имя скина и пользовательские картинки |

Интерактивная документация API: `http://localhost:8080/docs` (Swagger от FastAPI).
